### 수신 흐름 처리 
시작 찾기(AA 55) → 헤더 읽기(3바이트)→ 종류·길이 검사 → 데이터·CRC 수신 → CRC 검사

통신 제한시간
timeout = remaining + 전송 최대지연 + 수신 처리 최대지연 + 여유 

임시 timeout = 100ms로 두고 시간을 잡아 구체적인 timeout을 도출할것.

- 시작 표시의 첫 AA를 받으면 시간 측정 시작.
- 100ms 안에 헤더·데이터·CRC까지 모이면 검사 진행.
- 초과하면 불완전한 패킷을 버리고 시작 표시를 다시 찾음.

### 전송 주기

| 메시지 | 전송 시점 |
|---|---|
| Destination | 초기 |
| Current | 50ms마다 20Hz |
| Waypoint | 초기 |
| Output | Current를 받아 임무 처리가 성공할 때마다 — 정상적으로 약 100ms마다 |

### COMM_ERROR 설정

주기 50ms 이므로 5개가 연속으로 들어오지 않았을때 즉 250ms로 설정

| 상황 | 처리 |
|---|---|
| 최초 정상 Current 수신 전 | `COMM_ERROR` |
| 정상 Current 수신 | 수신 시각 갱신, `COMM_OK` |
| 마지막 정상 Current 이후 250ms 이상 경과 | `COMM_ERROR` |
| 정상 Current 재수신 | `COMM_OK`로 복구 |

### STM32 수신 방식 : 인터럽트

UART 데이터 도착
    ↓
수신 인터럽트: 바이트를 버퍼에 저장하고 다음 수신 준비
    ↓
Comm RX Task: 버퍼에서 꺼내 패킷 조립·CRC 검사·Parse
    ↓
기존 Data Manager → RX Queue → Mission Task

### 수신 버퍼 

원형 버퍼(ring buffer) 256bytes


### Notification 방식

UART 인터럽트
  → 받은 바이트를 원형 버퍼에 저장
  → 다음 바이트 수신 준비
  → Comm RX Task에 알림

Comm RX Task
  → 알림을 기다리며 대기
  → 깨어나면 버퍼에 쌓인 바이트를 꺼내 패킷 처리
  → 버퍼가 비면 다시 대기


### 패킷 연결 규칙

#### 0x01
- 목적지와 시작 명령을 임시 보관
- destination_valid, mission_command_valid를 true로 설정.
- 아직 Mission Task로 보내지 않음.
